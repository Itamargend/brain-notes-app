## What works

**Sync engine (`Packages/BrainNotesKit`)**

- First sync: tarball into a staging folder, every file checked against the recursive tree's blob shas, swapped in only then. Anything the tarball didn't deliver comes from the blobs API.
- Pull: ETag poll, compare, tree diff over 300 files, renames, deletes. Clean notes change on disk; dirty notes keep their text and merge at push.
- Push: one commit per batch from BrainMerge `planCommit`, tree on the head's tree, fixed op time as commit date, message ending in `Brain-Notes-Op: <uuid>`, `force: false` always.
- Races: 422 pulls, merges and retries up to 3 times with 1 to 4 s jitter, then Needs attention. Clean sections merge; a true clash keeps GitHub's text and writes my whole note to an `_inbox` conflict copy in the same commit.
- Lost responses: the commit and what it means for the device are written to the journal before the ref update. After a timeout, a 5xx or a kill, Verifying reads the ref and either finishes the landing, retries the same sha, or rebuilds. No duplicate commits.
- Typing during a push is kept: that note stays dirty, based on what was pushed, so GitHub's side of a merge survives the next push.
- Errors: 401 refreshes once, then Signed out with all data kept. 403/429 pause until the stated time. 404 is Access lost. 5xx and timeouts back off 2, 4, 8 s up to 5 min. A rejected op goes to Needs attention and the others still land. Offline makes no calls and catches up.
- Rewritten main stops sync and says so; a fresh sync keeps unsynced text as copies.
- Launch repair: a file that differs from the journal is a local edit, never overwritten; a missing file is downloaded, never treated as a delete; unsynced text comes back from the outbox after a device restore.
- Safety in code: the repo guard (`RepoTarget`) on every request, path policy, secret check on new text, tokens only in the Keychain, no secret anywhere, redirects only to GitHub's tarball host, no URL cache on disk, `privacy: .private` for paths and text.

**App (`App/`)**, one multiplatform target, iOS 26 and macOS 26

Folders home, note list with status dots and relative dates, rendered note view, editor with Hebrew RTL per paragraph and autosave, search (Hebrew and English, including Hebrew prefix letters and points), compose named from the first line, Inbox with conflict copies marked, Needs attention with both versions side by side and Keep both / Use this one / Restore, device-flow sign-in with big code, Settings, privacy cover in the app switcher, no Spotlight.

**Editor (`App/Sources/LivePreview.swift`, `MarkdownViews.swift`, `EditorToolbar.swift`, kit `MarkdownInline`, `MarkdownEdits`, `MarkdownTyping`, `MarkdownLists`)**

- Live Preview, as in Obsidian. The file stays plain Markdown, byte for byte, and looks rich: headings sized, bold bold, bullets, checkboxes, quote bars, rules, code bands, links in the accent colour. Syntax marks hide everywhere except in the paragraphs holding the caret or the selection, where they show, dimmed, for editing. No focus, no marks.
- The marks stay in the storage, with a near-zero font and no colour. So caret offsets, selection, copy (the source, as plain text), undo, saving and sync work as if every mark were on screen. Glyphs are drawn by a custom TextKit 2 layout fragment from an attribute. Nothing in rendering can reach the file: attribute changes fire no edit callback, and tests hold that.
- A tap on a checkbox changes one byte, leaves the caret, and brings up no keyboard. A caret arriving at a line's start goes behind its hidden marker, so typing doesn't break the heading or list.
- With VoiceOver on, nothing is hidden: what it reads and where the caret stops are what is on screen. Ticking is then an action on the line.
- iPhone bar, from the second phone test ("a flat dark strip" was out, Apple Notes' bar is the model): two capsules of the system's own glass floating above the keyboard, `UIGlassEffect` in a `UIGlassContainerEffect`, with nothing behind them but the note. Aa and the actions in one, Done in the other. 44 pt targets, the actions scroll inside their capsule if narrow, and a tap beside the capsules goes to the note. Aa (Title, Heading, Subheading, Body, Bold, Italic, Code, Indent, Outdent), Checklist, Bulleted list, Numbered list, Link (`[[]]` with the caret inside), RTL/LTR. It is on every note. With Reduce Transparency on the capsules are solid, and at large text sizes a long press shows a button large, as in the system's own bars.
- A heading or bold inside a list item works as anywhere: `- [ ] # **Shana` is a checkbox and a bold title, with every mark hidden until the caret is on the line, in the editor and in the note view. Body and the heading styles change a heading where it is, and the task stays.
- Return never breaks a link or a pair of marks. Inside `[[a]]` it goes behind the link. Inside `**a b**` both halves stay bold.
- Lists, bulleted, numbered and checklists alike. Return makes the next item, and splits the text at the caret. A task comes unticked, a number comes one higher, and a direction someone chose comes along. Return on an empty item goes one level out if it is nested, and otherwise ends the list: the marker goes and the line stays. Delete right behind a marker takes all of it. Indent and Outdent are in the Aa menu, and Tab and Shift-Tab do the same on a keyboard, with what is nested going along.
- Numbers stay on screen, as text, and the text of the items lines up, from `1.` to `99.`, with wrapped lines hanging under it. Nested ones hide their indent and draw it, as bullets do. A new item in a Hebrew list is on the right before its first letter, with no mark written to the file for that. Renumbering follows Return, ending a list, Indent, Outdent, the number button, deleting lines and pasting lines, as one undo step with the edit. Fenced code is left out of all of it, and tables are ordinary text to it.
- Tables, as in Notes (`TableGrid.swift`, `TableGridUIKit.swift`, `TableGridAppKit.swift`, kit `TableEdits`, `BrainNotesTables/TableGrid.swift`). A GFM table is always a real grid, in the note view and in the editor, focus or no focus, VoiceOver or not: its pipes are never on screen. A tap puts the caret in a cell, Return and Tab go on through the cells and Return at the last one adds a row, Shift-Tab goes back, and on a keyboard the arrows leave a cell from its edge and leave the table from its edge. With a cell in focus the grid has a handle for its row and one for its column, with menus (Add Row Above and Below, Add Column Before and After, Delete Row, Delete Column, Delete Table), and plus buttons for a row and a column at the end. A long press on the phone and a right click on the Mac have all of them, and so does the bar's table button while in a cell. That button otherwise inserts a 3 by 3 grid at once, with the caret in its first cell. Bold, italic, code, links and direction work in a cell. A Hebrew table runs right to left, each cell's text goes to its own side, and an empty table takes the direction of the line above it. A table wider than the note scrolls sideways.
- Mac: a Format menu with Cmd-B, Cmd-I, Cmd-Shift-L, Cmd-1/2/3 and Cmd-] and Cmd-[, and the same actions in the toolbar while editing, but for Indent and Outdent.
- Block actions work on every paragraph the selection touches, as one undo step. The direction mark stays behind `# ` and `- [ ] `. Return in a CRLF note stays CRLF.

**Status icon:** an icon in the navigation bar instead of "Saved on device" or "Synced" in words, on the note and on the home screen: synced, pending, offline, error. A tap says what it means, and on the home screen offers what can be done about it. VoiceOver gets the words. A failed save also stays in words, since it asks the user to do something.

**New Folder:** next to New Note in every folder and on the home screen, iPhone and Mac. On disk at once, on GitHub with its first note.

**Chrome:** true-black canvas (Apple Notes / X style) via `BrainChrome` — forced dark interface, lists and the editor sit on `Color.black` rather than system gray. **App icon:** B4 cut-out page mark in black-and-white (no blue fill) for light, dark, tinted, and Mac slots.

**Black-hole delete (Metal):** swipe, context menu, or note-screen Delete plays an original Telegram-style black hole driven by Metal (`BlackHole.metal` + `BlackHoleMetalView`). Behaviour follows the public write-up for riveauxmia/telegram-black-hole-delete as a design spec (Dynamic Island / top-capsule hole with a light ring, procedural note cards pulled along an arc and stretched near the horizon, collapse with a small spring) — no shaders, textures, or source copied from that repo. **Light** (~0.5 s) for a single note; **full** (~0.9 s) for a folder or ≥ 2 notes. Devices without a Dynamic Island grow the hole from a capsule just above the screen. Reduce Motion skips Metal for a short fade. After the store delete, a ~5 s Undo chip (`delete.undo`) restores via `NoteStore.save`. Folder rows with notes get a Delete confirmation; empty folders stay undeletable.

**Long-press peek:** long-pressing a note or folder shows an Apple Notes-style expanded preview (`contextMenu` + `preview:`) — note title and body snippet, or folder name/count and the first notes — then the context menu actions. No extra downloads.

**Onboarding (`App/Sources/Onboarding/OnboardingFlow.swift`)**

- Welcome, Connect, device code, Ready. `AppModel.showsOnboarding` decides, from the phase and nothing else: `.needsSignIn`, or a Ready screen still open. A launch that finds tokens never gets here, whatever `bn.onboarded` says, and that includes a Keychain that can't be read right now and a token GitHub has stopped accepting.
- `DeviceCodeView` is shared with the plain sheet from Settings: big code that stays left to right in a Hebrew layout, Copy, Open, a quiet countdown from `expiresIn`, and Get a new code when the code runs out or is declined.
- Ready shows first-sync progress from the engine's snapshot. Open My Notes waits only while notes are moving: every state a first sync can stop in says what happened and lets the user through.
- Try with Sample Notes opens the demo session in under 2 s, with no transport and no Keychain. Connect GitHub in Settings cancels its listener, drops the session, deletes `BrainDemo/` and opens the live session, ending in `.needsSignIn`. The live `Brain/` folder is never touched.
- Sign out and wipe returns to Connect, also after a kill. A kill before Ready starts at Welcome again. Offline on Connect says so and points to the sample notes, with no retry loop.
- The accent is the slate blue asset, #4A6FA5 and #7A9CD3, checked in a test.

**Demo mode**: `-BNDemoFixtures` or `BN_DEMO=1`. `-BNScreen live` opens the bilingual editor fixture in edit mode without StyleTimingLine (for screenshots). `-BNScreen search` seeds the query with `swiftui` (appears in English and Hebrew demo notes). Loads `Fixtures/demo-brain/` (50 notes), or `App/DemoFixtures/` (15) if that folder is missing from the bundle, onto the fake GitHub, then the real engine makes a conflict copy, a note deleted elsewhere and an unsynced note. `-BNScreen <folders|list|note|edit|search|compose|inbox|attention|conflict|signin|settings>`, `-BNHebrew`, and `-BNPhoneLayout` (the iPhone's navigation in a phone-sized Mac window). `-BNScreen <welcome|connect|code|ready>` opens an onboarding screen and implies demo mode with settings of its own, so `code` can't start a real device flow and `ready` can't mark the real app onboarded. `signin` now means Connect. `-BNScreen editor-spike` opens the Hebrew and English test note in the editor, in demo mode, with this device's style timing on screen. `-BNScreen table` opens a note with a table in the editor, a Hebrew one with `-BNHebrew`.

## Decisions worth checking

- **A table's source stays in the note's text, hidden, with a native grid over it.** The other way, cutting the note into text views and table views, would give up one caret, one selection and one undo stack across a note, and the 271 KB budgets. The file, the autosave, the sync, the merge and search see plain Markdown as before, and only the first line of a table is tall: as tall as its grid.
- **A cell edit is one line in the file, so edits merge.** Only the line that changed is rewritten, at once, so that the autosave has it as it has any typing. Two devices editing rows that aren't next to each other merge cleanly (`TableEditsTests`).
- **A table nobody edits keeps its bytes, however odd.** "Normalise on save" is done per table, at its first edit, and only for its shape: a ragged table becomes rectangular, and a row with more cells than the header gives the header and the delimiter row the cells they lack, so that what GitHub ignores becomes a real column and no text is lost. The other lines of a well-formed table keep their padding, because rewriting them would make every edit a whole-table conflict.
- **Text can't get into a table by being typed next to it.** A line right under a table's last row is another row of it on GitHub, and a table right under a list item is more of that item. So an edit near a table is tried out first, and it stands only if the tables around it are unchanged. If not, a blank line goes in to keep them apart (`TableEdits.typing`).
- **What isn't a table on GitHub stays text.** A delimiter row with the wrong number of cells, and a table inside a quote, show as what they are, pipes and all: there is no grid that could be saved back to them, and no text is lost.
- **A run of typing in one cell is one undo step,** as typing in the note is, and moving to another cell starts a new one. These steps are the overlay's own, on the note's undo stack: the text view's own would make every keystroke a step, since its typing run belongs to the first responder. Undo with a cell in focus goes through a forwarding `UndoManager`, as a shake, three fingers and Cmd-Z ask the first responder's.
- **One editor per grid, labels for the other cells.** A long table stays light, and the editor keeps the focus from cell to cell, so that the keyboard doesn't blink.

- **The bar is UIKit glass, not `ToolbarItemPlacement.keyboard`.** `UIGlassEffect` and `UIGlassContainerEffect` are UIKit's `.glassEffect` and `GlassEffectContainer`, the same material. The editor is a wrapped `UITextView`, whose `inputAccessoryView` is proven on the phone: SwiftUI's keyboard toolbar belongs to SwiftUI's own text fields, and nothing here can run it to find out. A `UIToolbar` draws glass too, but the first phone test's pill overlapped the keyboard ("the pill overlays the keyboard"). This bar's height is its own, with a set 8 pt gap above the keyboard.
- **The text runs on behind the glass.** At first SwiftUI's keyboard avoidance ended the text view above the bar, so the glass floated over the note's plain background, and that was to stay until the phone had judged it. It has: next to Apple Notes, Itamar found the bar not transparent enough. So the editor now ignores the keyboard's safe area (`NoteScreen`) and makes room for the keyboard itself, with its bottom content inset (`Coordinator.keyboardMoved`). The risk that held this back is still there, a caret hidden behind the keyboard. Its arithmetic is checked on real UIKit with made-up keyboard frames; the real keyboard is for the phone.
- **`[[sisi]]` wasn't a rendering bug.** The screenshot's `[[sisi` and `]]` are both plain white: no accent, no dim marks, so no link. The bar leaves the caret between the brackets, and Return after the name wrote a line break into the file. So the fix is in Return, and it stops new ones. **The note on the test repo will still hold that line break** (it can't be read from here, so this is from the screenshot), and nothing here joins two lines of a file on its own: delete it by hand and it is a link again. `testALinkAlreadySplitInTheFileStaysAsItIs` holds this. The same Return is the likely source of `**Shana` with no closing mark.
- **`**Shana` with no pair is bold to the line's end, which GitHub won't show.** The brief asks for its mark to hide. By CommonMark it is literal text, so GitHub shows the two stars. It only applies to `**` that can open and can't close: `2**n`, `*a` and `__a` stay as they are. It also means bold shows as soon as it is typed.
- **A heading inside a list item reads as one in all of them,** bullets, numbers and quotes too, not just tasks. For a bullet that is what CommonMark says. For `- [ ] # a` GitHub shows the `#`, since a task's text is a paragraph. Title on a task with no heading in it still replaces the task's marker.
- **A list is the lines that follow each other.** A blank line ends it, and so does a plain line with no indent, so two lists stay two and an edit in one leaves the other's bytes alone. To Markdown a blank line doesn't end a list, so a list written with blank lines between its items isn't renumbered across them. GitHub numbers those by itself either way.
- **Every number in a list is put right by a list action,** not only the ones after the caret, so `1. 1. 1.` becomes `1. 2. 3.` at its first edit. A top level keeps the number it starts with, and a nested list starts at 1. Typing in an item's text changes no number, and neither does opening or reading a note.
- **What is nested is what is at least 2 columns further in than the item above**, and not Markdown's rule, an item's text column. That one depends on how long the number is: `10. a` would turn `   1. x` under it into its sibling, number 11. So 2 space lists written by hand also keep the shape they have on screen here. What Indent writes is the exact column, so GitHub nests those too.
- **The first item of a list can be indented too**, as in Notes, though it has no item above to go under. GitHub shows that as an ordinary list.
- **A number is a marker now, not text a caret can stand in front of.** A caret arriving at a numbered line goes behind the number, as it does behind any marker, because what is typed in front would end the list. Once the line shows its marks, the caret can go anywhere. The earlier decision said the opposite, and two tests changed with it.
- **Delete right behind any block marker takes the whole marker**, for headings and quotes as well as lists, so that Return then Delete gets back what was there, and `-` or `#` isn't left on its own. A heading inside an item goes first.
- **Bullet or Checklist on a number replaces it**, and leaves the other numbers as they are. The earlier decision put the task in front of the number, as `- [ ] 12. a`, from before lists had a number button. Only the number actions renumber, so these two actions still never touch another line.
- **Marks hide, which f2 said they must not.** f2 cut hiding as the classic source of caret bugs. Itamar asked for it after the phone test, so it is built, and it also fixes the spike's worst look: a closing `**` landing on the far side of a Hebrew and English line. The caret risk is still there, and only the phone can judge it. See What to check on the phone.
- **An empty folder lives on this device until its first note.** Git has no empty folders. The other convention, a `.gitkeep`, can't work here: `checkPath` takes only `.md` files, so it could never leave the device, and BrainMerge is not to change. The prompt and the empty list say so. Another device sees the folder when its first note arrives.
- **Writing Tools stay in their panel.** In place, they would rewrite the text while the autosave and the styling carry on, and hidden marks are text to them, so a half-done rewrite could reach the file. The panel still offers them.
- **VoiceOver gets the source, not the rendering.** It would otherwise read and stop on characters that aren't on screen. Rendering stays for everyone else. Not run: VoiceOver needs a device.
- **A caret arriving at a line's start goes behind the marker.** A hidden marker takes no room, so a tap at the start of a heading could land in front of `# `, and typing there would end the heading. Once the line shows its marks, the caret can go into them.
- **The home screen's status is an icon too.** The feedback's words were about "synced" at the top left, and on the home screen that was the pill. Its tap used to act at once (sync, or open Settings). Now a tap explains, with the action one more tap away.
- **A selection of several lines:** Checklist and the like make them all one thing, or undo it if all already are. Blank lines get no marker. RTL/LTR makes the others follow the first line.
- **Title on a list line replaces the list marker**, since `# - [ ] a` would be a heading that reads "- [ ] a". The reverse, Checklist on a heading, keeps the heading inside the task, as the spike's test has it.
- **Hebrew italic is the upright font, skewed.** The system font has no Hebrew italic, so an italic font alone changes nothing. Latin stays true italic.
- **App icon: the iOS default slot holds the light version, not the dark one.** Asked for: default dark, plus light for the light appearance. Apple's format has no light slot: its default slot is the light-mode one (`actool` drops a `light` entry). So light is in the default slot and dark in the dark slot, and each appearance shows what was asked. The catch: places that ignore appearance, like an App Store listing, would show the light one. To swap, exchange the two file names in `AppIcon.appiconset/Contents.json`.
- **App icon on the Mac: the rounded dark PNG, on macOS's grey plate.** macOS doesn't round a square: it shows it, sharp corners and all, on a grey plate. A rounded PNG on the whole canvas looks best of the PNGs tried, but is still on the plate. A 1024 entry is the only Mac slot, so light and accent aren't on the Mac. An Icon Composer `.icon` file had no plate when tried (`.logs/b4/icon-composer-try/`), and could be added if wanted.
- **The Welcome mark is a corrected copy of `B4-cut-out-link-mark.svg`.** As delivered it draws a blank page: its brackets have `stroke="none"`, and it is white on a white screen. The copy has the same geometry with the brackets truly cut out, as a template image in the accent colour.
- **The plan's "landed" check is reversed, so I did not follow it.** A-app.md says `compare ours...head` status `behind`/`identical` means our commit landed. `behind` means head is *before* our commit, so it has not landed. Spike S1 measured `ahead` on a landed commit, and GitHub's docs agree. The code uses `ahead`/`identical`, with a test named `behindDoesNotCountAsLanded`.
- **The outbox holds the note's text, not just a hash.** That lets a push finish while note files are locked, and lets unsynced edits survive a device backup, which excludes the files. Journal protection is complete-until-first-unlock as the plan says, so unsynced text is readable after first unlock, like the base snapshots already are.
- **Saves carry the text they started from** (`editingFrom`), so an editor holding older text merges with a sync instead of overwriting it.
- **Backgrounding skips the one-commit-a-minute cap.** It may be the last chance for hours. Leaving a note respects the cap.
- **Notes this device can't hold stay on GitHub only**, listed in Needs attention: a case or NFC/NFD twin (`People/a.md` next to `people/b.md`), which gets its file once the name is free, and a name too long for the disk. The planner still sees them, so commits leave them alone.
- **Any 422 on the ref is a race**, as the plan says, whatever its message. Other 422s (a bad tree) park that op.
- **Deleting a note with unpushed typing** also writes that text to `_trash/<note>-unsynced-<time>.md`, since the plan says a delete never loses text. A note that never reached GitHub is simply gone.
- **A secret already on GitHub does not block.** Only a newly added one does; otherwise such a note could never be edited again.
- **Commit identity** is `Brain Notes <brain-notes-app@noreply.invalid>`, fixed so that a retry has the same sha.
- **Debug Mac builds have no App Sandbox**: a sandboxed ad-hoc build cannot host the in-app tests. Release has it, and was launched once in demo mode inside its container.

- **Black-hole intensity defaults to light for one note and full for a folder or multi-delete (≥ 2).** Everyday single deletes stay short so the effect does not tire; wiping a folder keeps the full Metal run.
