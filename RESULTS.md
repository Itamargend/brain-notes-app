# Spike S3 results: Swift port of the Brain Notes merge

Run on 3 Nov 2026 (18:23 UTC): MacBook Air (Mac16,12), Apple M4, 10 cores, macOS 27.2 (26B123), Xcode 27.2 (27B52), Swift 6.4.2. Logs from `scripts/verify.sh` are in `.logs/` (git-ignored).

## Verdict

**Pass.** The Swift package `BrainMerge` (no third-party dependencies, macOS 26 and iOS 26) reproduces the TypeScript reference in `spec/merge/ref/` exactly, and it is fast enough to run on the main device path.

Differential breakdown: diff3 300, freePath 150, splitBlocks 250, paths 500, matchLines 202 (including the 4,000,000-cell limit), path size limits 8, planCommit 418, mergeFile 951. In total that's 14 tests in 2 suites, all passing. No vector file was edited.

The Swift port compares and orders text the way JavaScript does: by exact UTF-8 bytes and UTF-16 code units. It doesn't use Swift's built-in String comparison, because String `==` treats NFC and NFD spellings as equal, counts `\r\n` as one character, sorts by Unicode scalar and has no final-sigma rule. See `Sources/BrainMerge/ExactText.swift`.

## Findings (spec changes need Itamar's approval; vectors unchanged)

### F1. The final guard rejects a valid twin cleanup (reference and Swift agree)

Random plan case R104: GitHub already holds the case twins `ǅ.md` and `ǆ.md`. A batch that edits one twin and deletes the other produces a write entry and a delete entry with the same clash key. The final guard (spec 7.6) then throws `plan bug: case clash ǆ.md`, and the whole commit fails. But deleting one twin is exactly how someone would resolve a twin pair, and a delete creates no file.
- **Fact:** the guard in `plan.ts` builds clash keys over every entry, deletes included.
- **Recommendation:** build the clash keys from write entries only. A write may share a key with a delete in the same batch. Add a vector for this case (edit one twin, delete the other), and have the app show a failed guard in Needs attention instead of crashing.

### F2. `foldKey` (NFC + lowercase) is weaker than APFS's own folding

I tested this on the Mac's APFS volume (case-insensitive). Each pair below collides on disk:

| Pair | Same file on APFS | Same `foldKey` |
|---|---|---|
| `ǅ.md` / `ǆ.md`, `Ǆ.md` / `ǆ.md` | yes | yes |
| `ΟΔΟΣ.md` / `οδοσ.md` | yes | yes |
| `ΟΔΟΣ/x.md` / `οδοσ/x.md` (sigma before `/` becomes final ς) | yes | **no** |
| `οδος.md` / `οδοσ.md` | yes | **no** |
| `Straße.md` / `STRASSE.md` | yes | **no** |
| `ﬁ.md` / `fi.md` (ligature) | yes | **no** |
| `ß.md` / `ẞ.md` | yes | yes |
| `K.md` (Kelvin sign) / `K.md` | yes | yes |
| `İ.md` / `i̇.md` | yes | yes |
| `İ.md` / `i.md` | no | no |

So the clash check can let through a GitHub pair that a Mac or iPhone can't hold both of. The final-sigma pair is already in the generator, G377 (`ΟΔΟΣ/x.md` with `οδοσ/x.md`): the reference accepts both edits, and on APFS they would land on one file.
- **Recommendation:** make the clash key a full Unicode case fold (NFKC_Casefold, or Swift's `folding(options: .caseInsensitive, locale: nil)` checked against APFS), and use the same fold in the TypeScript reference. Then regenerate the vectors. This mostly matters for German ß and Greek names, so keep it small and treat it as a spec change rather than a rewrite. Confirm the exact fold with a quick APFS test in S6, because iOS uses APFS too.

### F3. Minor
- In random plan cases, a time that isn't UTC ISO 8601 ending in `Z` throws an error (10 cases) instead of being normalised. This is intended input validation, so it isn't a bug. The app must always pass a `Z` timestamp.
