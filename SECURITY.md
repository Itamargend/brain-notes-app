# Security & Ownership

Brain Notes is built for a simple standard: anyone who installs the app should be able to connect **their own private notes repository** on GitHub and trust it with their brain — without trusting a Brain Notes server.

Your notes, your credentials, and your repository permissions stay between your device and GitHub. There is no Brain Notes backend, no account database, and no analytics tracker.

---

## How to verify this yourself (no code required)

You can verify all five guarantees in a minute:

1. **Your notes live on your device.** Turn on Airplane Mode and open Brain Notes. You can read every note, write new ones, edit tables, and search in English or Hebrew. Nothing depends on a cloud service staying up.
2. **Your repository is ordinary Markdown — on its own default branch.** Open your repository on GitHub in any browser. Every note is a plain `.md` file, and every sync is an ordinary fast-forward Git commit on your repository's default branch (`main`, `master`, `trunk`, etc.). If you delete Brain Notes tomorrow, your folder of Markdown files is still yours.
3. **Only the private repository you picked is ever opened.** When you install the Brain Notes GitHub App on GitHub, choose **Only select repositories** and select just your private notes repository. GitHub scopes the user token to the intersection of repositories you can access and repositories where the app is installed — and Brain Notes adds its own client-side guard locking every API call to the single private repository you selected. Public repositories are refused everywhere.
4. **Your GitHub password never touches the app.** Connecting GitHub shows an 8-character one-time code; when you tap **Copy code & open GitHub** the app copies it and opens `github.com/login/device` inside Apple's system authentication browser (`ASWebAuthenticationSession`). That window **shares Safari's GitHub sign-in** (not a private window), so you don't sign in twice and your saved passwords work. The trade-off is stated plainly in section 2 below ("Why Device Flow + ASW sheet"): an already-signed-in Safari could be a different GitHub account than you meant. So **nothing is saved until you confirm**: after you approve, the app asks GitHub who you are and shows **Connected as @login** with **Continue** and **Use a different account** (which uses a private window and a new code). On Choose notes, on the first-time **You’re all set** (`ReadyView`) screen, and in Settings, Brain Notes displays **Signed in as @login** alongside a single **Sign out** / **Sign out and wipe** control, and you can inspect or revoke access anytime at [github.com/settings/applications](https://github.com/settings/applications).
5. **Switching or signing out means a real wipe (without following symlinks).** In **Settings → Change notes…**, Brain Notes opens GitHub's installation configure page (warning first if you have unsynced edits) and wipes `<baseFolder>/Brain` (the previous repository's local files, SQLite journal `-wal`/`-shm`, pins, staging area, search index, `selected-repo.json`, orphan folders, and any legacy build-1 folders) and clears in-memory note/undo buffers once the replacement private repository is verified — cancelling on GitHub leaves current local notes untouched. In **Settings → Sign out and wipe**, it deletes `<baseFolder>/Brain` and `<baseFolder>/BrainDemo` (unlinking symlinks without following them and verifying both paths are gone), clears your stored selection, cancels any in-flight token refresh, and deletes your Keychain credentials. Your notes on GitHub are untouched.

## How the security boundaries work in code

If you are auditing the codebase, here is where each boundary lives and how it is enforced:

### 1. Multi-user double-guard, numeric ID routing & network lockdown (`Discovery.swift`, `PathPolicy.swift`, `GitHubHTTPClient.swift`, `NoteMover.swift`, `SyncEngine.swift`)
- **GitHub boundary + client installation verification (`GitHubDiscoveryClient`)**: GitHub only lets a GitHub App user-to-server token reach repositories that are **both** in an installation of the Brain Notes GitHub App **and** accessible to that signed-in user. On top of that, Brain Notes never trusts a stored or typed `owner/name` on its own: a repository can be opened only if it is present in `GET /user/installations/{installation_id}/repositories` for an installation returned by `GET /user/installations` for the active token, matched simultaneously by positive numeric `repoId` (`> 0`) **and** byte-exact `owner` **and** `name` (`sameBytes`). This check runs when selecting a repository, every time a session opens (`AppModel.launchRepairAndVerify` and `SyncEngine` installation re-verification, publishing `.checking` until installation and repository-privacy verification pass and `.firstSync(.downloading)` only afterward), before any move/rename operation (`NoteMover.remoteState()` calling `verifyPrivateRepo()`), and whenever a sync receives HTTP `403` or `404`. If the repository is no longer listed, syncing stops immediately and `RepoIssueView` offers both a non-wiping **Try again** (which updates any `default_branch` rename on the same `repoId` in place via `BrainSession.updateVerifiedSelection` without opening a second `NoteStore` or wiping local data) and **Choose your notes**.
- **User account binding (`SelectedRepo.userId` + mandatory `/user`, reconnect gate & rotated candidate token check)**: `SelectedRepo` persists the authenticated GitHub user's positive numeric `userId` (`Int64`) and `userLogin` alongside `repoId`, `installationId`, `owner`, `name`, and `defaultBranch` (decoding older files without `userId`/`userLogin` as having an unverified owner and hiding local notes until verified). On every live launch (`launchRepairAndVerify`), **Try again** (`retryCurrentRepository()`), `BrainSession.openVerified`, and `BrainSession` `installationCheck`, Brain Notes calls `GET /user` without `try?` and compares `user.id` against `selection.userId`: if `/user` fails for any reason, local notes remain hidden, sync does not start, and `RepoIssueView` shows a plain retry state (*"Can't check your GitHub account right now. Try again."* on network/server errors); if `/user` returns a different `userId`, it shows the same `@login` mismatch refusal as re-sign-in. `SyncEngine.setOnline(true)` syncs only when `started == true`, and `AppModel.setOnline(true)` never triggers engine sync while `!sessionOwnerVerifiedThisLaunch || repoIssue != nil` (instead re-running `retryCurrentRepository()` on reconnect when the account check had failed for a network reason). When re-signing in while a session or stored selection already exists, `AppModel.signedIn(pair:)` verifies the **candidate** token in memory via `GET /user` (`BrainAccount.verifyCandidateToken`) **before** saving to the Keychain or starting sync — returning and saving the latest `TokenPair` from the candidate store so single-use `ghr_...` refresh tokens rotated during verification are never saved already-spent.
- **Single-host, numeric-ID per-request guard (`RepoTarget.guardURL`) & fail-closed identity check**: After verification, all repository REST requests route by immutable numeric repository ID (`https://api.github.com/repositories/{repoId}/...`). Every request in [`GitHubHTTPClient`](Packages/BrainNotesKit/Sources/BrainNotesKit/GitHubHTTPClient.swift) passes through [`RepoTarget.guardURL(_:)`](Packages/BrainNotesKit/Sources/BrainNotesKit/PathPolicy.swift) twice: when the `URLRequest` is constructed and right before it goes on the wire. It rejects any scheme except `https`, any host except `api.github.com`, any URL carrying user credentials or port, any `..` or percent-encoded path traversal, and every REST path outside `/repositories/<picked repoId>/...` (including other numeric IDs and `/repos/<owner>/<name>/...`), plus `/graphql`. `fetchVerifiedPrivateRepo()` (`GET /repositories/{repoId}`) enforces fail-closed `guard let` checks on `id`, `owner.login`, `name`, `private`, and `default_branch` (throwing `GitHubError.repoAccessLost` if any field is missing or mismatched) and updates `default_branch` in place when renamed.
- **Strict identifier & branch validation (`PathPolicy.swift`)**:
  - `owner` must match `^[A-Za-z0-9](?:[A-Za-z0-9]|-(?=[A-Za-z0-9])){0,38}$`.
  - `name` must match `^[A-Za-z0-9._-]{1,100}$`, must not be `.` or `..`, and must not end in `.git` (case-insensitive).
  - Whitespace, slashes, percent-encoding, control characters, empty strings, and Unicode homoglyphs (such as Cyrillic look-alikes) are rejected; comparisons use byte-exact UTF-8 equality (`sameBytes`).
  - `default_branch` from GitHub is validated against Git ref rules (printable ASCII, max 255 bytes, no `..`, no `@{`, no leading `-`, no leading/trailing `/` or `.`, no `//`, not ending in `.lock`, no space or `~^:?*[\`), percent-encoded per `/`-separated segment in ref URLs (`getRef` and `updateRef`), persisted in `Brain/selected-repo.json`, refreshed on session open without wiping local notes, and used everywhere instead of hardcoding `main`.
- **Minimal discovery guard, 4 MiB cap & truncation detection (`DiscoveryGuard`)**: Non-repository calls go exclusively through [`GitHubDiscoveryClient`](Packages/BrainNotesKit/Sources/BrainNotesKit/Discovery.swift), whose `DiscoveryGuard.guardRequest(_:)` permits **only** `GET https://api.github.com/user` (no query), `GET https://api.github.com/user/installations`, and `GET https://api.github.com/user/installations/{positive_numeric_id}/repositories` (with positive integer `per_page` and `page` query items only). Every other endpoint (such as `/user/repos`, `/orgs/...`, `POST` requests, or non-numeric installation IDs) is refused before reaching the transport. Discovery replies enforce a **4 MiB** byte cap (`ReplyLimit.discovery`), check `Task.checkCancellation()` before every request/page, enforce an overall per-operation request budget (`defaultMaxRequests = 20`), and paginate up to `defaultMaxPages = 5` (`per_page = 100`), checking `seenRaw >= total_count` before the page-cap check so exact 500-item lists are not falsely marked truncated. If the page cap or request budget is reached before all items are scanned, `DiscoveryResult.isTruncated` / `SelectionVerificationError.truncated` surfaces a plain-language *"too many repositories — choose Only select repositories"* message instead of treating a truncated scan as `notListed` or auto-selecting.
- **Private repositories only**: Brain Notes is strictly for private notes. If a repository has `private == false` or `visibility != "private"`, it is greyed out and unselectable in the picker, refused at session open, and refused before every sync and move (`GitHubClient.verifyPrivateRepo()`), stopping sync with the plain message:
  > *"This notes repository is public, so anyone on the internet can read it. Brain Notes only opens private ones. Make it private on GitHub, then try again."*
- **Redirect stripping**: First-sync tarball downloads redirect to `https://codeload.github.com`. `RedirectGuard` rejects redirects to any other host, requires `GET` over `https`, and strips the `Authorization` header before following the redirect.
- **Capped replies & zero disk cache**: Every repository REST/GraphQL reply stops at 32 MiB (`ReplyLimit.json`), every discovery reply stops at 4 MiB (`ReplyLimit.discovery`), and every auth reply stops at 64 KiB (`ReplyLimit.oauth`), checked against `Content-Length` and enforced while streaming. `GitHubSession` uses `URLSessionConfiguration.ephemeral` with `urlCache = nil`, `httpCookieStorage = nil`, `httpShouldSetCookies = false`, `urlCredentialStorage = nil`, and TLS 1.2 minimum.
- **GraphQL variables + `databaseId` verification**: `lastCommitDates` passes file paths and the repository's validated `owner`, `name`, and `defaultBranch` strictly as GraphQL variables, never interpolated into the query string, selects `repository.databaseId` and asserts `databaseId == repo.repoId` (throwing `GitHubError.repoAccessLost` on any mismatch), and validates all object IDs as 40-to-64-char lowercase hex SHAs (`checkedSha`).

### 2. Why Device Flow + ASW sheet (and single `TokenManager`) (`Auth.swift`, `InAppWebSession.swift`, `Session.swift`, `SignInAndSettings.swift`)
- **Why not GitHub's Web Application Flow?**: Verified against GitHub's documentation (*"Generating a user access token for a GitHub App"*) and GitHub's 2025-07-14 PKCE changelog: GitHub's Web Application Flow for GitHub Apps **still requires `client_secret`** at the `POST /login/oauth/access_token` code-exchange step even when PKCE (`code_challenge` / `code_verifier`) is sent. Because Brain Notes has no backend server and a mobile or desktop app binary cannot keep a `client_secret` confidential, shipping a secret in the app is unacceptable.
- **Secretless Device Flow with strict bounds**: Brain Notes uses GitHub's Device Flow (`POST /login/device/code` and polling `POST /login/oauth/access_token`, plus refresh-token rotation) using **only** the public GitHub App Client ID (`BN_GITHUB_CLIENT_ID`), failing locally if `clientId` is empty. `DeviceFlow.start()` requires `verification_uri` to be `https://github.com/...` with `user == nil`, `password == nil`, and `port == nil`, clamps `interval` to `>= 5` seconds and `expires_in` to `1...3600` seconds, and advances `interval = max(interval + 5, echoedInterval)` on `slow_down`. Static tests in [`PolicyTests.swift`](Packages/BrainNotesKit/Tests/BrainNotesKitTests/PolicyTests.swift) scan every source file to enforce that `client_secret` never appears in code or requests.
- **Shared in-app browser, account check, and explicit `@login` display** (this **replaces the earlier BN-01 "always ephemeral" mitigation**): [`InAppWebSession.open(_:ephemeral:onFinish:)`](App/Sources/InAppWebSession.swift) sets `prefersEphemeralWebBrowserSession` from its `ephemeral` argument, which defaults to **`false`**. The device-verification, GitHub App installation, and Create-a-new-private-brain sheets therefore **share Safari's cookies and saved passwords**: someone already signed in to GitHub in Safari does not sign in again, and passkeys and password managers work, which matters most for non-technical users on a phone.
  - **The honest trade-off**: because the window shares Safari's GitHub session, an already-signed-in Safari account may be a **different GitHub account than the person intended** (a work account, a family member's). Mitigations, in order: (1) the person must still type or paste the code and press **Authorize** on a GitHub page that names the account; (2) **before anything is saved** — before the Keychain write, before `GET /user/installations`, before any repository is listed — Brain Notes verifies the new token with `GET /user` (`BrainAccount.verifyCandidateToken`, the pair held in memory only). Since build 7 there is **no confirm screen**: the check runs in the background and the code screen then shows a quiet **Signed in as @login** line with a **Use a different account** link (and Cancel) for as long as GitHub's access page is open, so the account is named before any notes are chosen; (3) the app can only reach repositories the person explicitly grants the GitHub App, and Brain Notes also refuses anything but the one private repository they pick; (4) with notes already on the device, `selection.userId` must equal the checked account's id before tokens are saved or sync starts (RB-01 / BN-02 / NB-04 are unchanged, and a mismatch still shows the plain message with **Sign out and wipe**).
  - **Use a different account** (and Cancel) during a first sign-in removes the just-saved token from the Keychain again (`AppModel.cancelFirstTimeSignIn`, which also stops the access-page polling and closes GitHub's page; a sign-in still being saved is stopped after its next wait and its token removed), requests a **new device code**, and opens the next browser with `ephemeral: true` (a private window with no Safari GitHub session). The choice is remembered for the rest of that onboarding run (`AppModel.privateBrowser`), so the GitHub App installation page and the new-repository page open privately too, and is reset on sign-out, on starting a new run from Connect, and once notes are chosen. The discarded token cannot be revoked by the app (revocation needs the `client_secret` that Brain Notes deliberately does not have); it is removed from this device, expires within hours, and can be removed at github.com/settings/applications. It never reached a repository: no notes are chosen before the person comes back from GitHub's access page.
  - **Stale sheet completions can't hide a live sheet**: each `open` carries a generation number and a replaced or cancelled sheet's late completion is ignored, so the programmatic close on approval always reaches the sheet that is actually on screen.
  - Right after the account check (no Continue step), Brain Notes opens GitHub's `installations/new` or installation configure page immediately rather than auto-picking an already-installed repository before the user visits GitHub; Brain Notes never auto-picks without a user grant, and on return from GitHub (always rechecking `GET /user` and never trusting a callback `installation_id` query parameter on its own) auto-connects only when a non-truncated "Only select repositories" grant yields a single repository that is private (showing `ChooseNotesView` whenever multiple repositories or "All repositories" were granted, and a minimal *Choose repositories on GitHub* / *Create a new private brain* screen when none were). That one repository opens the notes directly, with the first sync in the background; there is no ready screen. **Signed in as @login** is shown on the code screen while GitHub is open, on Choose notes, and in Settings. While GitHub's page is open, **Open GitHub** and **Cancel** always work (build 6 disabled every control while waiting, which looked stuck when the grant was unchanged and the page sat behind the app).
- **Polling and the pasteboard**: one `DevicePoller` per device code, results for an older code ignored by generation, one request per GitHub `interval` (never faster, including on returning to the foreground) with `slow_down` honoured; only a verdict, a token, or the code's expiry ends it, and every other failure is retried. The code is re-copied on each tap of the button, and on iPhone also when the app returns to the foreground while waiting (`localOnly` + `expirationDate` on iOS, change-count-checked removal on macOS) and removed when sign-in succeeds or the code ends. `?user_code=<code>` is appended to the (host-validated) `verification_uri` only through `AppConfig.prefillDeviceCodeInURL`, built with `URLComponents`; it is a code GitHub already shows on screen, not a credential.
- **Logging**: onboarding steps are logged under `com.itamargendelman.brainnotes` / `onboarding` as fixed strings and counts only; never tokens, device or user codes, logins, repository names, or note text.
- **Single shared `TokenManager`, wipe generation guard & background eviction**: [`BrainAccount`](Packages/BrainNotesKit/Sources/BrainNotesKit/Session.swift) owns a single `TokenManager` (and `TokenStore` + `HTTPTransport`) shared across discovery and any open `BrainSession` (the `config:`-based `BrainSession` helpers are `internal`). Sign-in and wipe call `TokenManager.reload()`, cancelling any in-flight refresh `Task` and bumping `generation` so a slow refresh returning after wipe can never write to the Keychain. On `scenePhase == .background`, `AppModel` cancels and **awaits completion** of `installPollTask`, `openVerifyTask`, and `discoveryTask` before evicting cached tokens (`flushInBackground` / `forgetCachedTokens`) so cancelled multi-page scans never reload tokens into memory while backgrounded. [`KeychainTokenStore`](Packages/BrainNotesKit/Sources/BrainNotesKit/Auth.swift) stores tokens with `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`.
- **No login-keychain fallback on signed Mac builds**: A team-signed Mac Release build uses only the Data Protection Keychain (`keychain-access-groups`) and never falls back to or migrates from the legacy login keychain (`errSecMissingEntitlement` fallback applies only to ad-hoc/unsigned Debug builds).
- **Reinstall hygiene & expiring clipboard**: `AppModel.installCheck` clears stale Keychain tokens left behind by a deleted previous install when `Brain/` and onboarding flags are absent. `DeviceCodeClipboard` marks the copied code `.localOnly` with `.expirationDate` on iOS and clears its exact pasteboard entry on macOS upon sign-in or expiry.

### 3. Per-repo local storage, symlink-safe full wipe & build-1 local data deletion (`FileStore.swift`, `Journal.swift`, `Discovery.swift`, `Session.swift`)
- **Isolated numeric repository folders, unbound-folder wipe & single-flight selection**: Each repository's local state lives under `Brain/<repoId>/` (keyed by GitHub's positive numeric repository ID, e.g. `Brain/123456789/`), while the non-secret selection metadata (`installationId`, `repoId`, `owner`, `name`, `defaultBranch`, `userId`, `userLogin`) lives in `Brain/selected-repo.json`. Whenever `Brain/selected-repo.json` is missing, unreadable, or corrupt at live launch (or before opening/selecting a repository with no active session and no readable stored selection), `<baseFolder>/Brain` is wiped with `LegacyBrainMigration.wipeFolderNoFollow` before any repository can open (failing closed with a plain warning if removal cannot be verified). `AppModel.selectRepository(_:)` is single-flight and stops + wipes any previously open session before opening another.
- **Symlink-safe full wipe scope**: Neither wipe nor legacy cleanup ever follows symlinks (`URLResourceValues.isSymbolicLinkKey` / `lstat` checks): if `<baseFolder>/Brain`, `<baseFolder>/BrainDemo`, or any child inside `Brain/` is a symbolic link, `removeItem` unlinks the link itself without enumerating or deleting its target, and nothing outside `<baseFolder>/Brain` and `<baseFolder>/BrainDemo` is ever deleted. `BrainSession.wipeForRepoSwitch()` stops the sync engine, closes the open `NoteStore` databases, wipes `<baseFolder>/Brain` (`Brain/<repoId>/`, `selected-repo.json`, orphan numeric folders, and any legacy folders), and drops all in-memory note lists, open editor references, and delete Undo/BlackHole snapshots (`AppModel.dropSession()`) *after* the replacement private repository is verified on GitHub and *before* opening the new session (cancelling on GitHub or failing verification leaves current local notes untouched). **Sign out and wipe** (`BrainAccount.signOutAndWipe` / `BrainSession.signOutAndWipe`) deletes `<baseFolder>/Brain` and `<baseFolder>/BrainDemo`, clears `selected-repo.json` and Keychain tokens, and verifies both paths are gone from disk (throwing and surfacing a plain warning if removal fails).
- **Build-1 local data deleted on update (`LegacyBrainMigration`)**: Build-1 carry-over/migration has been intentionally dropped — **testers on build 1 must sync on build 1 before updating**. On a live launch (never in demo mode), `<baseFolder>/Brain` and every legacy build-1 folder (`<baseFolder>/Brain/<non-numeric name>`) are marked `isExcludedFromBackup = true` until removed, and every non-numeric legacy entry under `<baseFolder>/Brain` is deleted immediately without reading, opening, parsing, or migrating any journal, SQLite database, or files inside it.
- **Excluded from backups & encrypted at rest**: `<baseFolder>/Brain`, `Brain/<repoId>/`, and any legacy folder prior to deletion are marked `isExcludedFromBackup = true` on iOS and macOS so iCloud backups and Time Machine never copy unsynced drafts or secret-scan-held notes. On iOS, `files/`, `files.staging/`, and `index/` use `FileProtectionType.complete`, while `Brain/`, `selected-repo.json`, and `journal.sqlite` use `FileProtectionType.completeUntilFirstUserAuthentication`.
- **Path traversal rejection, zero `UserDefaults` leakage, private logging**: `FileStore.url(for:)` rejects traversal segments; `UserDefaults` holds only three boolean flags (`bn.onboarded`, `bn.sampleMode`, `bn.installed`); `NoteStore` logs only via `os.Logger` with `privacy: .private`.

### 4. Git & content safety (`SyncEngine.swift`, `PathPolicy.swift`, `BrainMerge`)
- **Never force-push & resilient empty-repo bootstrap**: `updateRef` always sends `"force": false` (enforced by static test). When a newly created private repository is completely empty (0 commits; `404` or `409 Git Repository is empty` on ref/tree), Brain Notes opens an empty workspace cleanly without crashing or retry-looping, and bootstraps the repository's initial commit on `default_branch` via GitHub's Contents API (`PUT /repositories/<repoId>/contents/<path>`, after running `PathPolicy` and `SecretScan`) when the user saves their first note; if GitHub returns HTTP `422` (`unprocessable`) for one candidate operation, `bootstrapEmptyRemote()` parks that operation and tries the next unparked candidate in the same sync run. All subsequent commits use ordinary Git Data fast-forward commits.
- **Deletes go to `_trash/` & conflicts never overwrite**: Deleting a note moves it to `_trash/<path>` on GitHub. Concurrent edits merge via `BrainMerge` ([`docs/merge-spec.md`](docs/merge-spec.md)) and stage conflict copies in `_inbox/` + **Needs attention** rather than overwriting.
- **Pre-commit secret scan, 1 MiB note cap, and bounded first sync**: [`SecretScan`](Packages/BrainNotesKit/Sources/BrainNotesKit/PathPolicy.swift) blocks accidental pushes of tokens, AWS keys, PEM keys, and API secrets; dotfiles and `private/` are excluded; notes above 1 MiB are held back; tarball and blob downloads are strictly bounded by `FirstSyncLimits` (128 MiB compressed, 512 MiB inflated, 100,000 entries, 64 MiB per entry).

## Required GitHub App Configuration (for the app owner)

To support any user connecting their own private notes repository with zero server and zero `client_secret`, configure the **Brain Notes** GitHub App on GitHub with these exact settings:

| Setting | Required Value | Why |
| :--- | :--- | :--- |
| **GitHub App visibility** | **Public** | Allows any TestFlight / App Store user to install the app on their own private notes repository. |
| **App slug (`BN_GITHUB_APP_SLUG`)** | Matches the GitHub App's URL slug (default `brain-notes-app`) | Used to open `https://github.com/apps/<slug>/installations/new` during onboarding. |
| **Repository permissions → Contents** | **Read and write** | Required to read Markdown blobs/trees/tarballs and push note commits. |
| **Repository permissions → Metadata** | **Read-only** | Mandatory default on GitHub Apps; lets `/user/installations/{id}/repositories` list selected repositories and their `private` / `default_branch` fields. |
| **All other Repository, Organization & Account permissions** | **No access** | Least privilege: Brain Notes never asks for account-wide repo creation, issues, pull requests, workflows, emails, or profile writes. |
| **Enable Device Flow** | **Enabled (checked)** | Lets iOS and macOS authenticate users with only the public `Client ID` and no `client_secret`. |
| **Expire user authorization tokens** | **Enabled (checked)** | Issues short-lived `ghu_...` access tokens paired with rotating `ghr_...` refresh tokens. |
| **Request user authorization (OAuth) during installation** | **Disabled (unchecked)** | Web OAuth exchange requires `client_secret`; Brain Notes authenticates via Device Flow first and then installs/discovers repositories. |
| **Setup URL** *(optional)* | Blank, or `brainnotes://setup` | Optional fast-return deep link after installing the GitHub App; Brain Notes polls `/user/installations` while the sheet is open and does not depend on Setup URL being set. |
| **Webhook** | **Inactive (unchecked)** | There is no Brain Notes server to receive webhooks. |

## Reporting a security issue

Please do **not** open a public GitHub issue for security vulnerabilities. Report them privately via [GitHub Security Advisories](https://github.com/Itamargend/brain-notes-app/security/advisories/new) or email [itamar.gendelman@gmail.com](mailto:itamar.gendelman@gmail.com).
